1.1.13 is planned to supersede [1.1.12](/releases/1.1.12/) as a Stable security and maintenance
update. It does not withdraw 1.1.12. The supported line stays 1.1; Development stays 1.2.

## Before updating

- Export a configuration backup and keep console or hypervisor access available.
- Check HTTPS URL aliases, especially feeds using a private certificate authority. Install the
  appropriate trusted CA or repair the feed certificate before relying on its next refresh.
- Review delegated DNS administration. Custom DNS daemon configuration requires its own privilege;
  ordinary DNS settings can still be saved without granting control of custom options or scripts.
- Review VPN user names, saved custom daemon options and HA/API integrations against the stricter
  validation in this security batch. Names or values previously accepted may now be refused.
- Plan to sign in again when an account's credentials or enabled/expiry state changes.

The mandatory release test is an upgrade from 1.1.12 to the exact locked build, followed by a
reboot and service checks. A configuration backup is still required on ZFS; a boot environment
does not replace it. Upgrading from 1.0 to 1.1 remains one-way.

## Security changes prepared for this release

### Management access and system state

- Existing WebUI, widget and REST sessions recheck the current local account. Disabling or expiring
  an account revokes its sessions; password changes also revoke earlier sessions. Independent API
  keys keep their existing lifecycle.
- Directory logins cannot inherit local administrator privileges by sharing a local account name.
- WebUI, REST API, XML-RPC and package actions consistently enforce their request and privilege checks.
- Routing changes use private, validated state. An unprivileged temporary file cannot supply a
  command for the routing service to execute.
- Emergency WebUI recovery state is root-controlled, expires within 15 minutes and clears at boot.
- Configuration/cache/lock files are protected; sensitive configuration and debug logging receive
  stricter handling. Unused privileged upload and execution entry points are removed.
- Input validation is applied where saved configuration reaches daemon configuration, SQL or commands,
  including the earlier November security batch. This is broader than a browser-only check.

### DNS and alias feeds

- DNS Resolver and DNS Forwarder custom configuration have dedicated privileges. Ordinary delegated
  changes preserve protected fields; custom daemon options and resolver Python scripts require
  explicit authorization. Administrators retain access.
- URL alias downloads verify TLS by default, enforce transfer bounds and atomically replace data only
  after a complete successful refresh. A failed feed retains the previous complete list.
- Archive imports are streamed with resource limits rather than extracting arbitrary archive paths.

### Optional packages

The package preparation includes the existing NUT/HAProxy/Suricata-widget fixes and the syslog-ng
listener validation fix. The release also carries the BIND, TFTP, Tailscale and Web Gateway security
changes from the completed package audit:

- BIND validates zone names and quotes DNSSEC command arguments.
- TFTP file actions remain within the resolved server directory. Restore/delete require a protected
  POST request; ordinary file downloads and uploads remain available.
- Tailscale validates login-server/key inputs and safely formats service configuration arguments.
- Web Gateway blocks managed helper-program directives, including line-continuation bypasses.

Verify these package changes against the final locked Optional Packages commit before publication.

### Runtime components

The System inputs require Expat 2.10.0 or later and phpseclib 2.0.56 or later. The Suricata wrapper
requires engine 8.0.8 or later. Release validation must verify the actual installed versions and
current vulnerability audit results; dependency constraints alone do not prove a successful upgrade.

## Other fixes

- PPPoE uses the NAS IP and accounting interval saved in the RADIUS settings, with compatibility
  handling for older saved layouts.
- The kernel-memory status panel handles the FreeBSD 16 output format.
- Regression coverage checks the new boundaries and the shipped Composer inventory. Missing
  standalone smoke tests now fail CI.

## Platform and images

The proposed active FreeBSD pin uses source `769c49de261f`, ports `5975cd092a05` and OSVERSION
1600031; the final release lock remains the authority. This changes the FreeBSD base as well as
product code and requires appliance testing.

Retain the existing amd64 installer/cloud image coverage and generic arm64 UEFI installer coverage.
Raspberry Pi images remain Development-only. An architecture is available only after its own
publication succeeds; no draft or successful channel seal is proof that every image is downloadable.

## What to check after updating

Confirm the product version and selected Stable channel, reboot, then check WebUI/API access, WAN
traffic, IPv4/IPv6, DNS, routing, alias refresh, VPN/PPPoE, HA where used and installed package services.
Check service logs for rejected saved configuration and certificate/permission errors.
